# ci-gitlab

GitLab CI job templates for projects generated by `action-platform`. Logic lives in [ci-scripts](https://github.com/actionplatform/ci-scripts).

```yaml
include:
  - remote: https://raw.githubusercontent.com/actionplatform/ci-gitlab/v1/ci.yml

image: python:3.12
stages: [test, deploy]

check:
  extends: .ap-check
conventional-commit:
  extends: .ap-conventional-commit
gitflow:
  extends: .ap-gitflow
release:
  extends: .ap-release
```

Images for the languages added with ci-scripts v0.4.0 (each runs setup and check in the `Test` workflow):

| Language | Image |
|----------|-------|
| `csharp` | `mcr.microsoft.com/dotnet/sdk:9.0` |
| `elixir` | `elixir:1.18` |
| `swift` | `swift:6.0` (no curl; the templates install it when missing) |
| `scala` | `sbtscala/scala-sbt:eclipse-temurin-17.0.13_11_1.10.5_3.5.2` |

| Template | Does |
|----------|------|
| `.ap-check` | setup + lint + format + tests |
| `.ap-conventional-commit` | Conventional Commits on merge requests |
| `.ap-gitflow` | branch name and merge target follow git-flow |
| `.ap-release` | version bump on `vX.Y.Z` tags (needs `CI_PUSH_TOKEN`) |

The platform requires the checks `gitflow` and `conventional-commit` on merge requests into `main`, `master` and `develop`, so name the jobs exactly that.

Tag `vX.Y.Z`; `v1` floats to the latest.
